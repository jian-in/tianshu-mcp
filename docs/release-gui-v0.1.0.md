# 日志台 0.1.0 — 首个正式版

> 完整变更记录见 [CHANGELOG](../CHANGELOG.md)；功能文档见 [docs/gui-log-viewer.md](gui-log-viewer.md)。

Tianshu-mcp 日志台（`mcp-gui/`，界面名 **Tianshu-mcp 日志台 / Tianshu-mcp Logs**）的第一个**正式版**。
它是与 MCP server **完全解耦**的本地只读桌面应用：不依赖 server 在运行，直接读文件系统，把天枢落盘的
四类日志与任务产物统一到一个界面里查看。

---

## 本次「转正」意味着什么

0.1.0 之前，日志台走的是 `gui-v0.1.0-beta.N` 的预发布通道。正式版带来的是**发布链与产品定位的转正**：

- **同一份更新清单、同一条升级路径**：正式版与后续预发布版共用 `latest.json` / `latest-gitee.json`，
  按语义版本号比大小（`0.1.1-beta.1 > 0.1.0`），因此升级路径不会分叉；
- **正式版不再被标记为 Pre-release**：发行页按 tag 形态自动分流——含 `-beta.` / `-rc.` 才标预发布；
- **发行版正文就是本文件**：双语（中文在前、英文在后）随发行版一并发布，桌面的更新窗口直接显示它。

---

## 新增：更新日志面板

桌面上现在有**独立的更新窗口**（不再是设置面板里的一小块）：

- **发现新版本时自动弹出**：启动后静默检查，命中新版本即弹窗；被「忽略」过的版本不再自动打扰；
- **有忽略和更新**：「立即更新」直接下载安装；「忽略此版本」只压自动提示——
  **手动点「检查更新」仍会展示该版本**，且**出现更高版本时会重新提示**；
- **自动检测走哪个源**：每次检查都并发实测 Gitee 与 GitHub 两个清单端点，按可达性与延迟择优，
  弹窗里显式写出「本次将通过哪个源更新」及其探测结果；两端都不可达时回退上次成功使用的源并明确提示；
- **显示 release 更新内容**：弹窗正文即本发行说明（Markdown 渲染，禁用内联 HTML）——
  因此更新前就能读到这一版到底改了什么。

## 0.1.0 线的完整能力（首次接触建议从这节看）

### 数据目录

按与 MCP server **完全相同的规则**解析默认目录：环境变量 `TIANSHU_MCP_HOME`（非空即用），
否则 `~/.tianshu-mcp`。支持在多个数据目录间切换、追加与移除；追加时校验目录下必须存在 `logs/` 或 `tasks/`，
不合法即明确拒绝并给出原因。追加列表持久化在**系统应用配置目录**，**不写入项目目录**。

### 四类日志与任务产物

| 数据源 | 路径（相对数据目录） | 界面位置 |
|---|---|---|
| 全局运行日志 | `logs/server.log` | 侧栏「运行日志」 |
| 任务事件流 | `tasks/<taskId>/task.jsonl` | 工作区 · 事件流 |
| 原始执行日志 | `tasks/<taskId>/agent-<轮次>.log`、`verify-<轮次>.log` | 工作区 · Agent 日志 / 验收日志 |
| 验收报告 | `report-<轮次>.{md,json,html}`、`dry-run-report-<轮次>.{md,json}` | 工作区 · 验收报告 |

- **任务概览**：五格指标仪（任务总数 / 进行中 / 已结束 / 已成功 / 已失败）、状态圆片、任务卡网格、
  完整筛选浮层（关键字 / Agent / 状态 / 项目 / 起止时间 / 只看进行中）与排序；
- **事件流**：区分状态跃迁事件与细粒度 Agent 事件（`task_dispatched` / `confirmation_dialog_detected` /
  `awaiting_user_authorization` / `file_modification_started` / `rework_triggered`），`note` 单列为进度通道；
  无法解析的坏行**跳过但计数**并明确提示，不静默丢弃；
- **原始日志**：首屏只读尾部窗口（64 KiB）向前按块加载并显示「已加载 N / 共 M」；
  级别过滤、关键字高亮、行号与自动换行开关；**实时跟随**，手动上翻自动暂停跟随并可一键「跳到最新」；
- **验收报告**：Markdown 渲染、结构化卡片（检查项 / 耗时 / 退出码 / 输出尾部 / `changedFiles` / `diffstat` /
  `analysis.signals` / 阻塞问题）、视觉验收 HTML 在 **sandbox iframe** 内渲染（禁用脚本、注入 CSP、不联网）；
  干跑报告与常规报告**分开展示**，多轮报告可并排对比。

### 搜索 / 导出 / 复制

- **跨任务全局搜索**：范围可选（事件流 / Agent 日志 / 验收日志 / 验收报告 / 运行日志），
  结果按「任务 → 文件 → 行」分组并显示命中片段，点击跳转到对应视图与位置；按需扫描不建索引，带进度且**可取消**；
- **导出**：单文件导出原文；任务整包导出为 zip，可选排除体积大的原始日志并**如实回报**被排除的文件数；
- **复制**：任务 ID、任务目录绝对路径、当前日志全文均可一键复制。

### 界面语言、主题与设计系统

- **中英双语**可切换（默认中文）；主题三选一（跟随系统 / 浅色 / 深色，**深色为设计基准**）；
- 自研设计系统「黑曜石终端」，**零 UI 组件库、零外链、零字体文件**——完全离线可用；
  色值 / 字体 / 间距 / 圆角的唯一真源是 `mcp-gui/src/styles.css`；
- 版式：常驻左侧栏 + 两态内容区（任务概览 ↔ 全屏工作区），方括号状态标签、等宽数字（读数不抖动）、
  键盘可达并显示焦点环、遵循系统「减少动态效果」。

### 系统托盘与关闭行为

常驻系统托盘（Windows 通知区域 / macOS 菜单栏），右键给出「显示日志台 / 退出日志台」且**文案随界面语言即时切换**，
左键单击唤出并聚焦窗口。默认**关闭窗口 = 缩小到托盘**（应用继续运行），设置面板可改为直接退出；
macOS 另支持点 Dock 图标唤回窗口。

### 双源自动更新与故障自救

- 检查更新时**主动实测** Gitee 与 GitHub 两个端点（不依赖系统区域 / 时区），按可达性与延迟择优，
  结果按 TTL 缓存；两端都不可达则回退上次成功使用的源并明确标注降级；
- 设置面板提供**自动 / 强制 Gitee / 强制 GitHub** 三态开关，便于网络异常时自救；
- 更新包使用 **minisign 签名**，内置公钥校验，**验签不通过一律拒绝安装**；
- 检查 / 下载 / 安装任一步失败都**不影响日志查看主流程**，并给出跟随当前源的「手动下载」入口
  （经系统默认浏览器打开，仅放行 `github.com` / `gitee.com`）。

### 安全边界

对业务数据**全程只读**；唯一写入是应用自身偏好（系统应用配置目录）与用户显式选择的导出 / 更新临时文件。
所有「相对数据目录」的路径都做越界防护（拒绝绝对路径与 `..`）。不读取、不存储任何业务密钥，日志内容不外发。

## 已知限制

- **macOS 未做 Apple 代码签名与公证**：首次打开可能需要在「系统设置 → 隐私与安全性」中手动允许。
  这不影响功能，也不影响自动更新——更新包完整性由 minisign 签名保证；
- **macOS 仅保证 CI 构建通过（三平台矩阵含 macOS 双架构），未做真机功能验收**；
- **未提供 MSI**：Windows 仅 NSIS 安装器（Tauri updater 不支持 MSI，而 NSIS 安装器可直接复用为更新载体）；
- **未构建 Linux 版本**；
- **不提供任务写操作**：取消 / 返修 / 续跑仍走 MCP 工具；
- **不建本地全文索引**：搜索为按需扫描，超大日志目录下首次搜索较慢（可取消）；
- **浏览器预览（mock）无原生运行时**：托盘、关闭到托盘、真实下载安装只能在实际桌面应用中验证。

## 升级说明

- 从 `0.1.0-beta.9` 或更早的 beta 版本升级：**无破坏性变更**，安装包直接覆盖安装；
  应用偏好（语言 / 主题 / 更新源 / 数据目录 / 关闭行为）沿用，新增的「已忽略版本」字段缺省为空；
- 自动更新按语义版本比较，`0.1.0` 高于任何 `0.1.0-beta.N`，因此存量 beta 用户会正常收到本次升级提示。
